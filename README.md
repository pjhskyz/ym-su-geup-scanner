# YM리서치 수급 스캐너

기관·외국인 일별 순매수와 시가총액 대비 수급 비율을 함께 확인하는 정적 사이트입니다.
현재 서비스: https://ymresearch-scanner.netlify.app/

## 갱신 시각과 상태

- GitHub Actions는 **평일 16:00 KST**(`0 7 * * 1-5`, UTC)에 주 수집을 시작하도록 예약합니다. 기존 20:20·20:50 예약을 대체합니다.
- **16:20 KST**(`20 7 * * 1-5`)에는 당일 정상 16시 수집본이 없을 때만 예비 수집합니다. 정상본이 있으면 중복 조회·덮어쓰기를 건너뜁니다.
- 별도 기존 보고 자동화는 **16:30 KST에 보고 작성·Notion 저장을 시작**합니다. 예약·수집·배포 지연이 있으므로 수집 완료나 보고 전달 시각을 보장하는 뜻은 아닙니다. 당일 정상본이 준비되지 않으면 미갱신 상태만 알리고 과거 종목/Notion 보고서를 반복 생성하지 않습니다.
- 일반 요청은 평일 **15:40~15:59에 들어오면 16:00까지 최대 20분 대기**, **16:00~16:29에만 수집**합니다. 설치·큐 대기 뒤에도 시각을 다시 확인합니다. **16:30 이후, 주말, 기존 외부 cron의 20:05 요청은 건너뜁니다.** 외부 cron 자체의 예약은 변경하지 않았지만 저녁 데이터 재발행은 차단합니다.
- GitHub 예약이 늦게 도착해도 16:30 이후 집계로 16시 보고본을 대체하지 않습니다. 수집을 시작했더라도 발행 전 16:30을 넘기거나 당일 거래일 자료를 얻지 못하면 실패 처리하고 기존 정상본을 유지합니다.
- **2026-11-19(수능일)만 전체 일정이 1시간 순연**됩니다. 정규장은 10:00~16:30, 주 수집 **17:00**, 실패·미갱신 시 예비 수집 **17:20**, 보고·Notion 저장 시작 **17:30**입니다. 해당일은 16:40~16:59 요청을 최대 20분 기다리고, 17:00 이상 17:30 미만에만 수집·생성합니다. 16:00·16:20 예약 요청은 건너뜁니다. GitHub cron `0,20 8 19 11 *`은 연도 지정이 없지만 정확한 `20261119` 예외와 시간창 검증으로 다른 연도의 늦은 중복 수집을 막습니다. 다음 날은 일반 일정으로 돌아갑니다. 근거: [유안타증권 2026-11-13 공지](https://02.myasset.com/myasset/customer/notice/CU_0201000_P2.cmd?SEQ=202611131405580000000004&gubun=norNotice). 보고 단계에서도 당일 휴장/시간 변경 공지를 확인합니다.
- Actions의 `collection_window` 작업 요약에서 허용·대기·건너뜀 사유를 확인할 수 있습니다. 건너뛴 요청은 데이터와 마지막 수집 상태를 덮어쓰지 않습니다.
- 기준 거래일(`asof`), 데이터 생성 시각(`metadata.updated_at`), 마지막 수집 시도(`scanner_status.json`)를 구분합니다.
- KRX 인증·조회 실패 시 빌드는 실패로 종료하고 **마지막 정상 `scanner_data.json`을 유지**합니다. 별도 상태 파일을 발행해 최신 수집 실패를 표시합니다.
- 16시 정규 수집에서는 직전 거래일 폴백을 새 정상본으로 발행하지 않습니다. 명시적 강제 점검/별도 시각의 수집본은 `metadata.report_session=manual_or_other_time`으로 구분해 16시 자동 보고에 사용하지 않습니다.

## 순위의 정확한 의미

| 항목 | 정의 |
|---|---|
| 원천 전체 금액 순위 | KOSPI·KOSDAQ 해당 투자자의 순매수금액이 0이 아닌 전종목을 금액 내림차순으로 정렬한 순번입니다. 시총 500억원 및 화면 필터 적용 전입니다. 동률은 종목코드 오름차순입니다. |
| 기존 0.4% 구간 | `ceil(순번 / 모수 × 100 / 0.4)`. 같은 구간 번호에 여러 종목이 들어가며 실제 등수가 아닙니다. 종목 자체의 과거 수급 강도도 아닙니다. |
| 화면 Top 30 | 스캐너 수록 종목 중 양수 순매수를 비율(I1/F1) 또는 금액으로 정렬한 상위 30개입니다. 종목 수록 조건은 해당 거래일 시가총액 500억원 이상입니다. 따라서 원천 전체 금액 순위와 모수가 다릅니다. |
| 신규·유지·이탈 | 동일한 선택 기준의 직전 거래일 Top 30과 비교합니다. 하루의 여러 실행 결과끼리 비교하지 않습니다. 과거 이력 없는 ‘최초 포착’이나 ‘재진입’으로 확대 해석하지 않습니다. |

기존 JSON `rows`의 28칸과 구간 필드는 다른 소비자와의 호환을 위해 유지합니다. 정확한 금액 순위는 `rank_details[종목코드].inst/frgn.today/previous/two_days_ago`에 별도로 제공합니다. 순위가 없는 종목은 `null`이며 마지막 등수로 간주하지 않습니다.

## 수급 비율과 강한 쌍끌이

- I1/I5/I20: 기관 1·5·20거래일 누적 순매수금액 ÷ **기준일 시가총액** × 100(%).
- F1/F5/F20: 외국인의 동일 계산입니다.
- 기본 강한 쌍끌이: **기관과 외국인의 당일 비율이 각각 0.3% 이상**입니다. `rank_details.ratio_pct`의 반올림 전 값으로 판단합니다. 예를 들어 실제 0.299%는 화면에 0.30%로 보여도 통과하지 않습니다.
- 금액·비율 원값은 `rank_details.net_won/ratio_pct/cap_won`에 보관합니다. 표시용 `rows`는 기존처럼 백만원/소수점 둘째 자리/시총 억원 단위를 유지합니다.
- 신규 진입 비교는 직전 거래일의 **실제 원 순매수와 그날 시가총액**으로 `metadata.comparison`을 구성합니다. 현재 시총으로 과거 비율을 역산하지 않습니다. 자료 누락 시 비교 대기를 표시합니다.
- 기존 발행 파일에 원값 sidecar가 없다면 **백만원 단위 순매수금액과 억원 단위 시가총액으로 비율을 근사 복원**합니다. 이미 반올림된 값을 사용하므로 0.3% 경계와 근접한 순위는 실제 원값 계산과 다를 수 있습니다. 복구 데이터는 `method: published_snapshot`, `precision: published_rounded_amount_and_cap`으로 구분하며, 다음 정상 수집에서 제공하는 반올림 전 원값을 우선 사용합니다.

## 업종 분류 보존

WICS 조회가 비거나 일부 종목을 누락하면 마지막 발행본에서 확인된 동일 종목코드의 업종만 유지합니다. 과거 분류의 확인일은 반복 수집 후에도 유지하며, 화면에 보완 분류일·종목 수·미분류 수를 표시합니다. 처음 보는 종목의 업종은 추정하지 않습니다. `metadata.sector_classification`에 당일 조회일과 종목별 원분류 확인일을 별도로 기록합니다.

업종 서버 장애가 핵심 수급 발행을 오래 붙잡지 않도록 연결 5초·읽기 10초 제한을 두고, 3회 연속 오류가 나면 추가 조회를 중단합니다. 정상적인 빈 목록은 오류로 세지 않습니다. 조회 시작 후 60초가 지나면 새 요청을 시작하지 않으며, 중간에 확보한 분류는 유지하고 나머지는 기존 분류로 보완합니다. 요청별 제한은 전체 경과시간의 엄밀한 상한이 아니므로 정확히 60초 내 종료를 보장하지는 않습니다.

## 원천 집계 범위

빌더는 pykrx의 `get_market_net_purchases_of_equities`를 이용합니다. pykrx 원천은 KRX `MDCSTAT02401`이며 조회일·시장·투자자 구분을 전달합니다. 기관은 기관합계(7050), 외국인은 외국인(9000, 기타외국인 제외)입니다.

가격·수익률·시가총액은 해당 거래일 **KRX 정규장 일별 종가 기준**입니다. 수급은 **장마감 후 집계·최종 확정 전**으로 별도 표시합니다. 현재 수급 API에는 거래 세션 또는 ATS 범위 선택이 없으며 원천 확정 시각을 확인할 응답 필드도 없습니다. 따라서 **시간외·NXT 포함 범위는 미확인**이며, 16시에 조회했다는 사실만으로 정확히 15:30 정규장 거래분에 한정된 수급이라고 단정하지 않습니다.

`metadata.report_session=krx_close_1600`은 일반일 16:00 이상 16:30 미만에 수집·생성한 정상본입니다. **2026-11-19에는 `krx_close_1700`**을 사용하며 17:00 이상 17:30 미만의 실제 시작·완료 시각을 검증합니다. `metadata.schedule`의 주 수집·예비·보고·컷오프와 `price_basis.scheduled_close_kst`도 해당 거래일 기준으로 기록합니다. 실제 시작/갱신 시각, 예약 트리거, 가격 기준, 확정 여부를 함께 기록합니다. 전일 비교 API와 역사 파일은 과거 날짜의 재조회 집계이므로 직전 보고용 보관본과 동시간대 자료라고 단정하지 않습니다. 전환 첫날에는 직전 저녁 보고와 집계시점 차이가 있음을 명시하고, 저녁 최종값을 조기 보고의 단순 정정값으로 덮어쓰지 않습니다.

참고 원천 코드:

- https://github.com/sharebook-kr/pykrx/blob/master/pykrx/website/krx/market/core.py (`투자자별_순매수상위종목`)
- https://github.com/sharebook-kr/pykrx/blob/master/pykrx/website/krx/market/wrap.py (`get_market_net_purchases_of_equities_by_ticker`)

| 파일 | 역할 |

| `index.html` | 수급 조회 화면 |

| `test_scanner_data.py` | 순위·직전일 비교·실패 보존 검증 |

GitHub 저장소 Secrets의 `KRX_ID`, `KRX_PW`로 인증합니다. KRX가 비밀번호 변경을 요구하면 계정 비밀번호 변경과 Secret 갱신이 필요합니다. 인증정보는 JSON에 기록하지 않습니다. 수동 수집은 Actions의 `build-scanner-data` → `Run workflow`에서 실행합니다. 별도 시각에 점검하려면 **명시적 수동 점검(`force`)**을 켭니다. 기본값은 꺼짐이며, 명시적으로 켠 수동 실행만 시간·요일·중복 제한을 해제합니다. 별도 시각의 결과는 16시 자동 보고본으로 사용하지 않습니다.

```bash
pip install pykrx finance-datareader pandas
python -m unittest test_scanner_data.py test_collection_window.py
python build_scanner_data.py
python -m http.server 8000
```

미리보기는 http://localhost:8000/ 에서 확인합니다. JSON 조회 실패 시 과거 시드 데이터를 최신 데이터처럼 표시하지 않습니다.


## ETF 주도섹터

상단 **ETF 주도섹터** 또는 `/#etf`에서 한국 ETF 상대강도·소르티노, 미국·한국 종가 신고가 후보, 양국 관련 업종의 강도를 점검합니다. 가격 신호를 실제 ETF 순유입으로 표시하지 않습니다.

- 독립 수집 대상: 한국 60개, 미국 상장 104개. 미국은 국내·글로벌 업종/테마 100개를 분석 대상으로 두고 국가·배당 스타일 4개는 별도 관찰합니다. 실제 계산 가능 수는 매번 이력 길이·최신성·공식 종가 대조 결과에 따라 표시합니다.
- 첫 화면은 고정 대표 ETF(한국 54개·미국 상장 67개)를 우선 표시하고, **전체 ETF 목록**에서 등록된 164개와 보조·순위 제외 사유를 확인합니다. ETF 수는 중복 없는 산업 수와 다릅니다.
- 한국 전체 상장 ETF 공개 목록을 별도로 수집해 신규 후보를 발견합니다. 검토 후보는 운용사 노출 검증 전 자동 순위 편입하지 않으며, 목록 관측 시각과 가격 기준일을 구분합니다.
- 유니버스 v3 확대일은 2026-10-11입니다. 1·5·20거래일 순위 변화는 확대된 동일 집합으로 소급 계산하며, 이전 v2 순위와 직접 연결하지 않습니다.
- 한국은 KOSPI, 미국은 SPY 대비 21·63·126거래일 가격수익률 차이를 산출합니다. 소르티노는 126일을 기본으로 하며 10·20·50일선 조건을 선택합니다.
- 현재 순위와 전일·5·20거래일 비교는 계산 가능 범위와 비교집합을 명시합니다. 자료 부족·재조회 실패는 0이나 순위 유지로 바꾸지 않습니다.
- 배당 포함 총수익률 및 원본 대시보드의 산식과 구분합니다. 기업행위 조정 검증 전 고점은 후보입니다.
- 독립 수집 시작 예정: 매일 07:15 KST, 아침 보완 07:45 KST, 평일 20:35 KST. GitHub 예약은 실행 지연·누락이 가능하므로 해당 시각의 반영 완료를 보장하지 않습니다. 원본 저장 참고 표는 자동수집 대상이 아니며 별도의 관측 기준일을 표시합니다.
- ETF 주도섹터·구성변동은 열린 화면을 5분마다 재조회하고, 화면 복귀·탭 재진입 때도 마지막 조회가 5분 이상 지났으면 다시 읽습니다. 서버 원자료 수집과 화면 재조회는 별개이며, 수동 새로 확인은 공개된 최신 결과를 다시 불러옵니다.
- 실행/산식/데이터 계약은 [ETF_DATA.md](ETF_DATA.md), 갱신 기록은 [ETF workflow](https://github.com/pjhskyz/ym-su-geup-scanner/actions/workflows/etf.yml)를 참조합니다.

## ETF 구성변동

상단 **ETF 구성변동** 또는 `/#holdings`에서 국내 76개 ETF(기존 60개+시장 액티브 16개)의 날짜별 구성 비중과 종목별 통합 변화를 확인합니다. 기본 대표 54개와 시장 액티브 16개에서 2개 이상 ETF의 비중이 증가한 종목을 모아 **평균 비중 변화가 높은 순**으로 표시합니다. 보조 ETF 포함·업종/시장·운용사·직전/5거래일 비교를 선택할 수 있습니다. 시장 액티브는 구성 추적 대상으로 추가하며 기존 업종 가격 순위에 혼합하지 않습니다.

전체 구성이 확보된 두 날짜만 비교합니다. 비중 증가와 실제 매수는 다르므로 확인 가능한 CU 기준 구성수량 변화도 함께 표시합니다. 초기 이력 부족·미갱신·조회 실패는 0건으로 표시하지 않습니다. 원천·산식·보존 방식은 [HOLDINGS_DATA.md](HOLDINGS_DATA.md)를 참조합니다.

ETF별 순자산총액과 기준일, 비교 시작일 순자산을 곱한 **비중 변화 환산액**도 제공합니다. 통합 환산액은 축소분도 차감하고 확보된 ETF 수를 표시하며, 평균순/환산액순 정렬을 선택할 수 있습니다. 기준일 미제공 규모는 참고 표시만 하고 환산에 사용하지 않습니다. 환산액은 실제 순매수액이 아닙니다.

`build_research_data.py`는 네트워크를 쓰지 않고 방금 발행된 `scanner_data.json`·`stocks_data.json`만 읽어 `research_data.json`을 만듭니다. `build-scanner-data` 워크플로에서 시장지표 생성 직후 실행되며, 실패해도 시장지표 발행을 막지 않고 기존 파일을 유지합니다.

산식은 YM 자체 정의입니다. 공급자 업종지수(WI26 등)나 KRX 규모별 지수와 구성·산식이 다르므로 수치를 직접 비교하지 않습니다.

- 업종 수익률: 업종 내 종목 일간 수익률의 **기준일 시총** 가중 평균입니다. 과거 시총을 보관하지 않아 과거 날짜에도 기준일 시총을 씁니다(근사).
- 업종: 스캐너에 수록된 FnGuide WICS 대분류 10개. 미분류 종목은 업종 지표에서 제외하고 히트맵에는 `미분류`로 표시합니다.
- 상승 업종 비율: 당일 수익률이 0보다 큰 업종 수 ÷ 계산 가능한 업종 수.
- 상승 종목 비율: 스캐너 수록 종목(시총 500억원 이상) 기준이라 전 종목 ADR과 다릅니다.
- 상위권·나머지 격차: 업종별 20거래일 누적 수익률 상위 3개 평균 − 나머지 평균(%p).
- 쏠림 변화: 격차의 5일 평균 − 20일 평균.
- 시총 구간별 지수: 기준일 시총 1~100위 / 101~300위 / 301위 이하의 시총가중 수익률을 첫 관측일 100에서 누적.
- 일간 수익률은 수정주가가 아닌 원시 종가 비율입니다. 가격제한폭(±30%)을 넘는 변화는 분할·병합·신규상장으로 보고 업종·구간 계산에서 제외합니다.
- 히트맵 타일 면적은 시가총액의 제곱근입니다. 종목 등락률은 스캐너 수록값(소수 첫째 자리)입니다.
- 주도섹터 점수: ETF의 벤치마크(KOSPI/SPY) 대비 21·63·126거래일 가격 상대강도 평균. 반등 관찰: 126거래일 상대강도가 음수이고 21거래일 상대강도가 63거래일보다 개선된 폭.

결측은 0이나 직전 값으로 채우지 않습니다. 컨센서스·수출입 화면은 자료 파일이 생기기 전까지 예시 수치 없이 준비 안내만 표시합니다.

### 수출입 분석 켜기

1. [공공데이터포털](https://www.data.go.kr/)에서 아래 관세청 API 다섯 개를 **같은 계정으로** 활용신청합니다(무료, 개발계정 API마다 하루 10,000건). 인증키 하나를 함께 씁니다.
2. GitHub 저장소 Settings → Secrets and variables → Actions에 `DATA_GO_KR_KEY`로 등록합니다. Encoding 키와 Decoding 키 어느 쪽이든 됩니다.
3. Actions의 `build-research-sources` → Run workflow.

| API | 주소(`https://apis.data.go.kr/1220000/…`) | 화면에서 쓰는 곳 |
|---|---|---|
| 관세청_품목별 수출입실적(GW) | `Itemtrade/getItemtradeList` | 품목별 월별 수출입(금액·중량) |
| 관세청_품목별 국가별 수출입실적(GW) | `nitemtrade/getNitemtradeList` | 품목 상세의 국가별 수출·수입 |
| 관세청_국가별 수출입실적(GW) | `nationtrade/getNationtradeList` | 국가·지역 탭 |
| 관세청_수출 주요품목별 10일 단위 잠정치 통계 | `prlstMmUtPrviExpAcrs/getPrlstMmUtPrviExpAcrs` | 수출 잠정치(주요 품목) |
| 관세청_수출 주요국가별 10일 단위 잠정치 통계 | `cntyMmUtPrviExpAcrs/getCntyMmUtPrviExpAcrs` | 수출 잠정치(주요 국가) |

수집 주기(평일 23:20 KST, 잠정치 공표일 전후 1~3·11~13·21~23일은 10:10 KST에 한 번 더):

- **품목별 월별 실적**: 첫 실행은 품목마다 5년치(61개월), 이후 최근 3개월만 다시 받아 정정치를 반영합니다.
- **잠정치**: 처음에는 5년치, 이후 매번 최근 13개월을 다시 받습니다. 1~10일 누계는 11일, 1~20일 누계는 21일, 월 전체는 익월 1일경 공표됩니다.
- **국가별·품목별 국가별 확정치**: 목표 월(15일 이후 전월)이 들어올 때까지는 매번 확인하고, 들어온 뒤에는 7일마다 다시 받습니다. 국가·지역은 5년치, 품목별 국가 분해는 24개월입니다.

읽는 법과 한계:

- 추적 품목과 관련 종목은 `trade_pipeline/items.json`에서 고칩니다. HS 코드는 2~10자리. 코드를 바꾸면 그 품목은 월별 실적과 국가 분해를 처음부터 다시 받습니다.
- 확정치는 금액 USD·중량 kg, 통관 기준입니다. 매월 15일경 전월 실적이 공표되며 이후 정정될 수 있습니다. 수출은 최종 목적국, 수입은 원산국 기준입니다.
- 잠정치는 **수출만** 제공되고 수출신고 수리일 기준입니다. 관세청이 정한 주요 품목 10개(반도체·철강제품·승용차·석유제품·무선통신기기·선박·자동차부품·컴퓨터 주변기기·정밀기기·가전제품)와 주요 국가 10개(중국·미국·유럽연합·베트남·홍콩·일본·대만·인도·싱가포르·말레이시아)만 있어 추적 품목 23개와 분류가 다릅니다. 원자료 단위 천 달러를 달러로 바꿔 저장합니다.
- 전년 동기·전월 동기 대비는 **같은 구간 누계끼리** 비교합니다(예: 11월 1~20일 ↔ 전년 11월 1~20일). YoY·MoM과 마찬가지로 조업일수 보정 전입니다.
- 국가·지역 탭은 전체(모든 국가 합), 유럽연합 27개국 합산, 아세안 10개국 합산, 최근 12개월 수출+수입 합계 상위 40개국을 보관합니다. 지역 합산은 회원국 실적을 직접 더한 값입니다.
- 품목 상세의 국가별 실적은 수출·수입 각각 최근 12개월 누계 상위 6개국과 그 외 국가입니다. 비중은 국가별 합계 대비입니다.
- 실적이 공표된 달에 기록이 없는 국가는 그 달 실적을 0으로 봅니다. 공표 전인 달은 비워 둡니다.
- 품목 하나나 구역 하나(국가별·잠정치)가 실패하면 그 부분만 직전 값을 유지하고 화면에 실패 건수를 표시합니다. 품목별 월별 실적을 한 건도 받지 못하면 기존 파일을 유지하고 워크플로가 실패합니다.
- `trade_status.json`에는 최근 수집의 구역별 상태와 이번에 받은 응답의 항목명(`fields`)이 남습니다. 명세와 실제 응답이 달라졌을 때 확인하는 용도입니다.

## 로그인과 회원 승인

사이트는 **구글 계정으로 로그인하고 관리자가 승인한 사람만** 볼 수 있습니다. 화면뿐 아니라 자료 파일(JSON), 시세 프록시(`/yf/*`), 야간선물 Function 까지 같은 기준으로 막습니다.

| 상태 | 권한(`app_metadata.roles`) | 볼 수 있는 것 |
|---|---|---|
| 로그인 전 | — | 로그인 화면(`/auth/*`)만 |
| 승인 대기 | 없음 | 로그인 화면의 "승인을 기다리고 있습니다" 안내만 |
| 회원 | `member` | 스캐너 화면과 모든 자료 |
| 관리자 | `admin` | 위 전부 + 회원 관리 화면(`/admin.html`) |

흐름: 구글 로그인 → 가입 요청이 **승인 대기**로 등록 → 관리자가 `/admin.html` 에서 **승인** → 요청한 사람의 대기 화면이 1분 안에 자동으로 넘어감("승인되었는지 확인"을 누르면 바로). 관리자에게는 상단 계정 이름 옆에 대기 건수가 표시되고, 이름을 누르면 회원 관리·로그아웃 메뉴가 열립니다.

### 구성

- `_redirects` — 접근 규칙. `Role=` 조건은 Netlify 가 로그인 쿠키(`nf_jwt`)의 서명을 검증해 판단합니다. 공개 경로는 `/auth/*` 하나뿐이고, 나머지는 `member`·`admin` 만 통과하며, 그 밖의 요청에는 로그인 화면을 401 로 돌려줍니다.
- `auth/login.html`, `auth/login.js`, `auth/auth.css` — 로그인·승인 대기 화면.
- `auth/auth.js` — 브라우저용 로그인 도우미. 외부 라이브러리 없이 Netlify Identity 의 표준 주소(`/.netlify/identity/authorize`·`token`·`logout`)만 씁니다. 로그인 상태는 쿠키 두 개(`nf_jwt`, `nf_refresh`)에만 두고, 여러 탭이 동시에 토큰을 갱신하지 않도록 잠금을 겁니다.
- `auth/session.js`, `auth/session.css` — 상단 계정 메뉴와 로그인이 풀렸을 때의 처리.
- `auth/auth_logic.js` — 권한 판정 등 순수 로직(브라우저·Function·테스트 공용).
- `admin.html`, `admin.js` — 회원 관리 화면.
- `netlify/functions/members.mjs` — 목록·승인·해제·관리자 지정·삭제. 호출한 사람이 관리자인지 Identity 에 다시 물어 확인합니다.
- `netlify/lib/identity.mjs` — Function 공용 로그인 확인. `kis-night` 도 이 확인을 거칩니다.

### 처음 켤 때 (Netlify 화면에서 한 번)

이 설정은 코드로 할 수 없고 Netlify 프로젝트 설정에서 직접 해야 합니다. **아래를 마치기 전에 이 변경을 `main` 에 병합하면 아무도 로그인할 수 없으니 순서를 지킵니다.**

1. 프로젝트의 Identity 설정에서 **Identity 를 켭니다**.
2. 가입 방식(Registration)은 **Open** 으로 둡니다(누구나 요청은 할 수 있고, 승인 전에는 아무것도 볼 수 없습니다).
3. 외부 로그인(External providers)에 **Google** 을 추가합니다(기본 설정 사용).
4. 배포 미리보기 주소에서 본인 구글 계정으로 한 번 로그인해 "승인을 기다리고 있습니다"가 뜨는지 확인합니다.
5. Identity 의 사용자 목록에서 본인 계정을 열고 역할(Roles)에 `admin` 을 넣습니다. 첫 관리자만 이렇게 지정하고, 이후는 회원 관리 화면에서 처리합니다.
6. 다시 로그인해 화면이 열리고 `/admin.html` 이 동작하는지 확인한 뒤 병합합니다.

### 운영 메모

- 로그인은 브라우저를 닫아도 30일 동안 유지됩니다(공용 PC 에서는 로그아웃, 사파리는 브라우저 정책상 7일). 접근 토큰은 1시간짜리이고 만료 5분 전부터 자동으로 갱신됩니다.
- 승인 해제·삭제는 이미 로그인한 기기에는 **최대 1시간 뒤**(토큰 갱신 시점)에 적용됩니다.
- 거절(삭제)한 계정도 다시 로그인하면 새 요청으로 올라옵니다.
- 관리자는 본인 권한을 스스로 내리거나 삭제할 수 없습니다(관리자가 0명이 되는 것을 막기 위함).
- **저장소가 공개이면 GitHub 에서 자료 파일을 그대로 볼 수 있습니다.** 사이트 로그인만으로는 막히지 않으므로 저장소를 비공개로 바꾸고 GitHub Pages 배포를 꺼야 합니다. 비공개 저장소는 GitHub Actions 무료 사용량(월 2,000분)을 씁니다.
- Function 의 URL(`/.netlify/functions/*`)은 `_redirects` 로 막을 수 없어 각 Function 이 직접 로그인을 확인합니다. 새 Function 을 추가할 때는 `currentUser()` 확인을 넣습니다.
